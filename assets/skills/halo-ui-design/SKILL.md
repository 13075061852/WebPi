# 网页与界面设计

本技能是对社区项目 [open-claude-ui](https://github.com/Caho1/open-claude-ui) 的精选适配，不是 Anthropic 官方标准，也不代表上游效果已在当前项目实测。用于 AI 生成的网页与界面，不自动改变星环应用本身的样式。

## 选择设计方向

1. 先看用户要求、参考图、目标项目的样式与组件。已有设计系统时沿用其颜色、字体、间距和组件，只补充缺失的交互细节；局部修改不扩展为整站换肤。
2. 没有既定方向时，以克制、温暖中性色、清楚的信息层次为默认起点。按行业与内容调整布局，不把所有网站都做成聊天窗口或卡片网格。用户指定其他风格时保留其方向。
3. 需要默认配色、圆角、控件或动效数值时，读取 [references/design-guide.md](references/design-guide.md)。这是一组可适配的基准，不是每个页面必须照搬的模板。
4. 沿用项目技术栈。原生 HTML/CSS/JS 可直接实现，无需为采用规范安装 React、Tailwind 或 Framer Motion。单文件交付将必要 CSS/SVG 内联，不能依赖星环安装目录或本技能绝对路径。

## 实施重点

- 先确定主任务与主要操作，再安排导航、内容和辅助控件。减少重复标题、装饰性大卡片和无用途说明；同类控件保持尺寸、对齐和反馈一致。
- 用表面明度、留白和轻分隔建立层级，避免容器、内层卡片、按钮层层描边。正文和交互状态仍需足够对比度，不能为了“低对比”牺牲可读性。
- 图标遵循应用已有的 SVG / `icon_library` 规则；不复制 Claude 商标、专有字体或录音，不用 emoji 替代界面图标。
- 折叠、弹窗和切换应有短而连续的过渡，退出动画完成后再卸载内容；尊重 `prefers-reduced-motion`，不靠动画延迟按钮响应。
- 独立面板按自身宽度适配。窄屏先收缩间距、让操作换行，再折叠次要文字；不能压成单字竖排，不能隐藏唯一操作入口。
- 表单处理中文输入法合成，Enter 提交前检查 composition 状态。弹窗处理焦点、Escape 和关闭后焦点恢复；图标按钮有可访问名称。
- 流式输出仅在用户位于底部时跟随滚动，向上阅读时不抢滚动位置。错误信息简短可理解，技术详情按需展开；不擅自增加自动重试或打断当前任务的行为。

## 验证与交付

按实际改动验证正常、窄屏、长文本和键盘操作；有深色主题与减少动态效果时一并检查。使用可用的内部预览观察真实页面后再声称已验证；没有运行条件时明确说明验证范围。不得把上游声称的“生产级”“逆向验证”当成当前生成页面已通过实测的证据。
